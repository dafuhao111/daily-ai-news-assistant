# 每日 AI 简报：真实 API 前端

Vue 3 + Vite + JavaScript。三个页面分别为每日简报、历史简报、身份与订阅，均通过 `/api/v1` 访问本机后端。凭据只保存在后端环境配置中；前端不配置 `VITE_*` 密钥。

## 启动

需要 Node.js 22.12+ 或 24 LTS，以及已完成环境配置、数据库迁移的后端。

开发时分别在两个终端启动：

```powershell
cd backend
uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```powershell
cd frontend
npm ci
npm run dev -- --port 5173 --strictPort
```

打开 <http://127.0.0.1:5173/>。Vite 将 `/api` 代理到 `127.0.0.1:8000`，无需开启跨域访问。

日常使用可先在 `frontend/` 执行 `npm run build`，再启动后端，打开 <http://127.0.0.1:8000/>。后端仅提供 `frontend/dist`，不会提供项目目录或 `.env`。构建完成后再启动后端；更新前端后重新构建并刷新页面。预览命令 `npm run preview -- --port 4173` 也使用相同 API 代理。

Windows 上执行 `npm ci` 前先停止本项目的 Vite/预览服务，避免占用 `esbuild.exe`。日常已有依赖时无需反复安装。

## 使用流程

1. 在“身份与订阅”保存称呼、可选角色和本人收件邮箱。个人资料可以先单独保存。
2. 选择至少一个话题，填写可选关键词与排除词，保存资料与偏好。默认未保存的时间字段为 `08:30 / Asia/Shanghai`；订阅默认停用。
3. 点击“立即运行”，后端真实创建 Agent 任务；页面读取后台任务状态，没有模拟执行步骤。停用订阅仍可手动生成，但不会发信。
4. 在“历史简报”按报告日期筛选；同日多次任务分别保留，生成失败记录与空简报分开显示。最多每页 30 条，可加载更早记录。
5. 原文弹窗区分 AI 概括与来源摘录，保留来源链接和时间；来源未提供发布时间时明确标注。

准备启用推送时，先确认后端 SMTP 已配置，点击“发送 1 封测试邮件”，实际收件后点击“我已收到测试邮件”。随后保存启用状态，并在后端配置 `SCHEDULER_ENABLED=true`、重启服务。页面只在调度器真正安排任务后显示下次执行时间。开启真实推送会发送至已验证的本人邮箱。

“已提交发送”仅表示 SMTP 接受请求；未知状态不提供盲目重发。投递失败的重试使用该份已保存简报，不重新调用模型。

## 数据与错误边界

每日简报右侧现显示项目 Token 总额、已确认、待核对预留、请求中预留及可用额度，来自只读 `/api/v1/budget`；没有前端增额或清零入口。预算停止是任务 limited 状态，与真实模型服务失败区分。实现背景见[技术方案](../docs/技术方案.md)。

- 旧 Demo 已移到 `demo/`，仅供回归测试；生产源码禁止导入。旧 localStorage 中的 Demo 配置不会迁移或启用真实推送。
- 资料、偏好、简报、任务与投递记录来自数据库。首次使用没有示例新闻。
- API 有请求超时；页面提供加载、空结果、网络错误与重新连接入口，保存失败保留输入。资料与偏好分两次提交，若后者失败会明确提示个人资料已保存。
- 手动任务使用幂等键；丢失响应后重试复用键。刷新页面后从后端恢复正在运行的任务。浏览器仅暂存未确认请求的随机幂等键，无凭据。
- 按产品文档，用户页面不展示 Agent 工具轨迹；开发者使用 `backend/` 下的 `uv run --locked python -m app.diagnostics RUN_ID` 分别读取真实模型工具请求、执行结果和最终状态。

## 验证

```powershell
npm test
npm run build
```

自动测试使用模拟 HTTP 响应，覆盖页面、表单、接口错误、异步竞态、任务恢复、幂等键、弹窗焦点以及生产代码与 Demo 的隔离；不会访问真实模型、RSS 或 SMTP。

安全修复使用 Vitest 5 和修复版传递依赖，需 Node 22.12/24 或兼容版本。当天已完成任务再次点击时明确提示复用，不伪装为新任务或重复投递。
