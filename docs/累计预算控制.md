# 项目累计 Token 预算控制

完成日期：2026-11-22。预算按整个项目输入 Token + 输出 Token 合计，跨任务、用户、手动运行、定时任务、开发验收及真实模型测试共享。不是每日或每月重置额度；普通页面和模型都不能修改上限。

## 实现与停止规则

迁移 `0005_token_budget` 新增 token_budget、token_usage。账户保存总额、确认消耗、请求预留、待核对预留和冻结状态；流水仅保存随机请求 ID、数字、状态和时间，不保存密钥、URL、Prompt、工具输出或邮箱。

每次模型 HTTP 请求都经过 BudgetHTTPClient，包括直接使用 create_chat_model 的真实测试，不依赖某个页面或任务结束后才统计：

1. 发送前计算保守额度：UTF-8 请求 JSON 字节数 + 本轮最大输出 Token + 服务商封装预留（默认 8,192）。消息、工具 Schema、参数、重复提交的历史均在 JSON 中，不按缓存折扣减少 Token。
2. 用数据库原子条件更新检查 `已确认 + 请求预留 + 待核对预留 + 本次预留 <= 总额`。额度不足、不存在账户或数据库不可用时，网络请求不会发出；并发请求不能重复使用同一余额。
3. 收到合法 usage 后按实际 input_tokens + output_tokens 结算；兼容 Responses 和 Chat Completions。若返回 total_tokens，必须与两项之和一致。相同请求重复处理不能重复扣减。
4. 超时、取消、非成功 HTTP、缺失/异常用量或结果不明，保留整个预留作为待核对金额。进程突然退出时，原先已提交的 reserved 行仍占额度；**不按定时器、重启或重试自动退款**。
5. 若供应商报告实际 Token 超出预留，或忽略最大输出限制，则据实记账并冻结后续请求，必须本地核对。不会忽略差额、自动增额或把失败调用当零消耗。
6. Agent 显示 limited 与预算原因；已有工具结果、真实轨迹和旧简报保留，未完成草稿不保存为成功简报、不发送邮件。工具选择仍由 LLM 决定，预算耗尽不是伪造正常结束。

当前只允许非流式、单份、文本/Function Calling 请求；服务端保存的 conversation/previous_response_id 和未受控的多输出请求不放行。SDK 自动重试继续为 0，显式重试每次都独立预留。

这是**本地额度硬拦截与保守预留**，不能控制第三方平台在请求发出后怎样计费，也无法保证供应商虚报/隐藏额外 Token 时绝对不超出账单。预留可能提前拒绝实际本可负担的小请求。历史安全预留也不能证明所有历史调用的真实费用；仍建议在中转站设置独立额度限制并核对账单，但本次未修改第三方账户。

## 使用和配置

本机已经迁移并初始化，不需要再次执行 initialize。查看：

```powershell
cd backend
uv run --locked python -m app.budget status
uv run --locked python -m app.budget pending
```

每日简报页面显示“项目 Token 预算”，分别列出总额、已确认、待核对、请求中预留、可用额度；`GET /api/v1/budget` 只返回安全摘要，没有写接口。额度不足按下一轮请求的完整预留判断，因此可用大于零也可能无法再启动模型请求。

新安装环境先执行 `uv run --locked alembic upgrade head`，再按账单/已知历史初始化一次：

```powershell
uv run --locked python -m app.budget initialize --limit 1000000 --prior-confirmed 118771 --prior-uncertain 200000
```

上述历史值是当前项目的历史快照，不是其他新项目的默认费用。已有账户再次初始化会返回 budget_already_initialized，**不会清零或改变上限**；没有每日重置或普通 API 增额功能。不要删除预算表或降级迁移来释放额度。迁移降级会删除账本，不能用于业务恢复。

`backend/.env.example` 新增 `LLM_BUDGET_REQUEST_ALLOWANCE_TOKENS=8192`，仅控制每轮封装安全预留。项目总额保存在数据库，不随 .env 改动或应用重启清零。其他单任务字节、轮次、时间与输出限制继续生效。

供应商确认某个不确定请求的用量后，先停止后端并确认相关模型请求已结束，再按 pending 中的 request_id、UTC 时间与账单核对，才可运行；不得把仍在执行中的 reserved 请求提前结算：

```powershell
# 两个数字必须替换为该请求账单确认的实际输入和输出 Token，不得随意填零。
uv run --locked python -m app.budget reconcile REQUEST_ID --input-tokens ACTUAL_INPUT --output-tokens ACTUAL_OUTPUT
```

确认账本启用**之前**的全部历史总 Token 后，用历史范围总数释放初始安全预留，不把启用后的账单重复计算：

```powershell
uv run --locked python -m app.budget reconcile-history --confirmed-total VERIFIED_PRE_LEDGER_TOTAL
```

此值不能小于已知历史 118,771；重复一致操作幂等，不一致操作拒绝。追加调整流水，保留后续实际调用用量，不重置累计消耗。没有可靠账单时保持安全预留，不运行此命令。

供应商超出预留导致冻结时，先核对全部不确定请求和历史，再按服务商口径调整封装预留；只有无悬而未决预留、确认用量仍小于项目上限时，显式 `uv run --locked python -m app.budget acknowledge-overrun` 才能解除冻结。此命令不退款、不增额，有审计流水。真正达到总上限时它也拒绝恢复。
