# 本地部署、配置与完整演示

范围：本机单用户、loopback、一个后端进程。现有本机 MySQL、模型、网易 163 凭据继续使用，不需要重新提供密码或 API Key。不要覆盖已存在的 .env，不把其内容复制到聊天或 Git。

## 1. 环境与安装

- 推荐 Python 3.12，最低 3.11；backend/.python-version 选择 3.12，本机为 3.12.13。旧版 3.10 无法使用修复后的 DNS 依赖。
- Node.js 22.12/24 或兼容版本；本机为 24.18.0。安全修复后使用 Vitest 5，不能继续使用旧版 Node。
- MySQL 8、utf8mb4、独立项目账号仅访问项目库；本机 8.0.41 已验证。需要 uv，无需 Redis 或额外搜索账号。

从项目根目录执行：

```powershell
cd frontend
npm ci
npm run build
cd ../backend
uv sync --locked --extra dev
```

仅当新机器没有环境文件时，才复制 backend/.env.example 为 backend/.env，在本地编辑。已有 .env 跳过复制。保留 uv.lock 与 package-lock.json，不把 replace_me 当成有效配置。

## 2. 环境变量

预算迁移后需一次性初始化项目账户；当前本机已完成，不要重复初始化或清表。查看额度、历史安全预留、每轮封装参数及账单核对命令见 [累计预算控制](累计预算控制.md)。未初始化时真实模型请求会被拒绝，测试和显式验收命令同样受保护。

秘密只放 backend/.env 或后端进程环境，不使用前端 VITE_* 注入。

| 配置 | 要求 |
|---|---|
| DATABASE_URL | `mysql+pymysql://项目账号:URL编码后的密码@127.0.0.1:3306/项目库?charset=utf8mb4`；不使用 root，不提交实际值 |
| LLM_BASE_URL / LLM_API_KEY / LLM_MODEL | 本机已验证 `https://cn.happycodeapi.com`、`gpt-6.1-sol`；Key 仅本地填写。中转站需要账号和有效额度，按供应商账单收费 |
| LLM_API_PROTOCOL | 本机 responses，使用根地址，不自行追加 /v1；其他供应商按文档选择 chat_completions/responses |
| LLM_MAX_OUTPUT_TOKENS | 默认 2048，每轮输出上限，不是项目总预算 |
| AGENT_MODEL_TIMEOUT_SECONDS | 默认 45 秒，每轮请求限时，SDK 自动重试为 0 |
| AGENT_MAX_TOOL_ROUNDS / AGENT_MAX_CALLS_PER_ROUND | 默认 8 / 8，超限明确受限结束 |
| AGENT_MAX_MODEL_INPUT_BYTES / AGENT_MAX_TOTAL_INPUT_BYTES | 默认 128000 / 512000，消息及 Schema 的单次/累计本地序列化上限，不能作为账单 Token |
| AGENT_TASK_TIMEOUT_SECONDS | 默认 300 秒；新闻工具另有单次超时和大小限制 |
| RSS_SOURCES_FILE | 本机 config/rss_sources.json，可复制示例文件；只配置可信官方源与明确 allowed_hosts。当前公开源无需账号或 Token |
| AGENT_WORKSPACE_DIR | 可选，默认当前用户 LocalAppData/DailyAINewsAssistant/workspaces；保持用户私有，不指向源码、秘密或不可信共享目录 |
| SMTP_HOST / SMTP_PORT / SMTP_SECURITY | 本机 smtp.163.com / 465 / ssl；现有网易邮箱需开通 SMTP、生成授权码。限速、额度或付费要求以服务商实际规则为准 |
| SMTP_USERNAME / SMTP_FROM_EMAIL | 都填本人完整邮箱，例如 your_name@163.com（示例） |
| SMTP_PASSWORD | 网易 SMTP 授权码，不是邮箱登录密码；仅后端读取 |
| SMTP_TIMEOUT_SECONDS / SMTP_MAX_ATTEMPTS / SMTP_RETRY_BASE_SECONDS | 默认 15 秒 / 3 次 / 60 秒；有限指数退避，不确定结果不自动重发 |
| SCHEDULER_ENABLED | 验收为 false；确定开启每日任务时改 true 并重启，还需保存启用状态和验证邮箱 |
| FRONTEND_DIST_DIR | 可选，默认仓库 frontend/dist；只应指向构建产物，不能指向整个仓库或秘密目录 |

收件邮箱在界面保存，发件账号在后端环境配置，模型不能指定或修改目标。API Key、SMTP 授权码和数据库密码不属于用户资料。

## 3. 迁移、运行与更新

在 backend 目录执行：

```powershell
uv run --locked alembic upgrade head
uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

打开 <http://127.0.0.1:8000/>。只提供 frontend/dist，前后端同源。没有构建时根路径 404，API 仍可用。

日常不用 --reload，不启动第二个生产进程，不绑定 0.0.0.0。MySQL advisory lock 选出恢复/调度进程，行锁、条件更新与唯一键保护入队和领取；不是多实例集群方案。

更新时停止本项目 Uvicorn/Vite，同步依赖、重建前端、执行迁移、再启动。不要结束电脑上所有 Node/Python 进程。Windows 安装时 esbuild 占用应先停止原开发服务。

开发可另在 frontend 执行 `npm run dev -- --port 5173 --strictPort`，预览可用 `npm run preview -- --port 4173`；两者的 /api 均代理到 8000。

服务不会自动随系统启动。后续若配置 Windows 服务/任务计划程序，应使用当前 OS 用户、固定 backend 工作目录、同一单进程命令，保护 .env。此次没有设置开机托管，也没有部署长期新推送。

## 4. 一次完整演示

不发邮件的普通流程：

1. 在身份与订阅保存称呼、可选角色和本人邮箱。修改邮箱需要重新验证。
2. 选择话题、关键词、排除词，设置 08:30、Asia/Shanghai；保持订阅停用并保存。
3. 点击立即运行。观察真实任务状态，LLM 根据工具结果继续决策；不要求每次调用全部工具或重复固定顺序。
4. 成功后查看摘要、相关性、来源时间与原文；在历史中选日期并刷新核对持久化。失败或无合格新闻分别显示。
5. 当天已有完成/空结果时再次点击会复用结果，不重复正常生成或发信；失败可重试。投递重试只使用对应已保存简报。

需要额外真实生成时，普通 API 不绕过每日防重；开发验收可以显式运行：

```powershell
cd backend
uv run --locked python -m app.acceptance --live
```

此命令读取真实 RSS、消耗模型额度，只生成、不发送。只有本人明确同意本次收件后才运行：

```powershell
uv run --locked python -m app.acceptance --live --send-verified-email
```

要求目标已保存并验证、SMTP 已配置、没有活跃任务。命令建立独立验收任务，以一次性计时器运行生产协调器，最多一次 SMTP 尝试，不启动每日 Cron 或重试扫描；临时启用后恢复开关。若发现并发用户修改则保留其修改并报告恢复未应用；强杀进程会阻止 finally，需要人工复核开关，不能盲目重跑发送。

记录返回 run_id，在 backend 执行 `uv run --locked python -m app.diagnostics RUN_ID`，区分模型决策、工具请求、执行结果和最终状态。普通页面不展示开发轨迹。

真正开启每日任务时，先保存邮箱、发送一封测试邮件、本人实际收到后点击我已收到测试邮件，再保存启用状态；将 SCHEDULER_ENABLED 改 true 并重启，确认实际下次执行时间。启动可能补做当天已过计划时间且未完成的任务，因此开启可能立即产生一封今日简报。

电脑、网络、MySQL 与后端必须运行。恢复只处理当天，旧日期不补发。submitted 是 SMTP 接受，unknown 不盲目重发，不承诺停机期间准时执行。

## 5. 测试与公告检查

默认回归不调用付费模型：

```powershell
cd backend
uv run --locked pytest -q
uvx ruff check .
uvx ruff format --check .
uv lock --check
uv run --locked python -m compileall -q app tests migrations
cd ../frontend
npm test
npm run build
npm audit --audit-level=moderate
```

显式真实模型/RSS/MySQL 检查（有调用费用）：

```powershell
cd backend
$env:RUN_REAL_LLM_TESTS = "1"
$env:RUN_LIVE_RSS_TESTS = "1"
$env:RUN_MYSQL_TESTS = "1"
uv run --locked pytest -q --junitxml=data/acceptance-final-tests.xml -o junit_family=legacy
Remove-Item Env:RUN_REAL_LLM_TESTS
Remove-Item Env:RUN_LIVE_RSS_TESTS
Remove-Item Env:RUN_MYSQL_TESTS
```

MySQL 测试仅建立随机测试用户和关联记录，finally 清理，不删除数据库、不联系 SMTP；自动测试不向真实用户发信。模型两项测试把返回的用量写为 JUnit 属性。避免无目的重复付费测试。

后端依赖公告命令：`uvx pip-audit --path .venv/Lib/site-packages --progress-spinner off`。不能审计未发布的本地应用本身。
