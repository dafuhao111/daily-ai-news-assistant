## 文档边界与实现

产品文档第 2、7.4、9 节要求用户页面只展示简报、运行及投递状态，工具轨迹仅供本地开发排障。因此没有新增用户 Agent 轨迹页，也没有将工具参数、任务偏好快照、系统提示词或邮件凭据返回前端。技术方案中的开发诊断面板本阶段采用本地命令行实现，避免扩展 MVP 页面；输出区分模型工具请求、对应执行结果和最终任务状态，不输出模型内部思考或原始材料。

| 目标 | 联调结果 |
|---|---|
| 身份资料 | GET/PUT profile；称呼、可选角色、可选本人邮箱；邮箱改变后重新验证；可先单独保存个人资料 |
| 订阅偏好 | GET/PUT preferences；话题、关键词、排除词、时间、IANA 时区、启停状态存入数据库；失败保留输入 |
| 最近简报 | GET briefs/latest；返回最近已保存简报，最新任务失败时仍可阅读此前内容；无简报返回 null |
| 历史 | GET history，按 report_date 筛选，offset/limit 分页；同一天不同任务分别保留；失败任务也可查看 |
| 历史详情 | GET briefs/{id}；展示生成时间、摘要、相关性、真实来源、原文及投递状态；按本机用户归属过滤 |
| 任务 | POST runs 创建真实后台任务；GET status/runs/{id} 读取排队、运行、完成、无新闻、失败或受限结果；轮询不伪造执行进度 |
| 邮件 | 对接已保存邮箱的测试、实际收件确认和指定简报的投递重试；submitted 与 delivered 不混用；unknown 不盲目重发 |
| 配置与调度 | status 返回 SMTP 是否配置、调度器是否运行、实际计划任务的下次时间，不返回秘密 |
| 同源运行 | 开发及预览由 Vite 代理 /api；构建后由 FastAPI 仅托管 frontend/dist |
| Demo 隔离 | 旧数据和计时逻辑移到 frontend/demo；保留原有 17 项 Demo 回归测试；增加生产代码禁止导入 Demo/测试夹具的检查 |

资料和偏好是两个独立的已有 API，界面顺序提交；如果偏好保存失败，会明确说明资料已保存、偏好未保存，不伪装成整体成功。订阅启用与后台调度开关分别显示，避免仅保存开关就声称每日任务已安排。

## 真实端到端操作

使用本机 MySQL 8.0.41、已配置的 Happy Code 备用 Responses 接口和 `gpt-6.1-sol`，以及 OpenAI、Google DeepMind、Microsoft Research 的真实 RSS；凭据来自 Git 忽略的 `backend/.env`。

1. 在浏览器打开开发页面，读取已保存且已验证的个人邮箱资料，不修改邮箱或重发测试邮件。
2. 页面保存推荐偏好：大模型与研究、Agent 与工具、AI 工程；关键词 Agent、开源模型；时间 08:30、Asia/Shanghai；`enabled=false`。`SCHEDULER_ENABLED=false` 始终保持。
3. 点击“立即运行”，收到后端任务，页面显示真实运行状态。任务 ID：`079ce755-72ec-4c92-bbfb-36e5b86424e1`。
4. 模型返回 4 轮决策，3 轮包含工具调用：1 次 fetch_rss、5 次 fetch_article、再 2 次 fetch_article。8 次工具请求均由模型返回的 Tool Calls 发起。两次原文请求被 URL 白名单拒绝，错误已返回模型，模型自主继续后续读取并结束。
5. 服务端校验成功，保存简报 ID 1，5 条中文摘要、相关性与真实来源；投递记录为 `skipped / subscription_disabled`，没有发送新闻邮件。
6. 在页面查看最近简报，打开原文弹窗核对 AI 概括与来源摘录分开显示。
7. 切换历史，刷新页面后仍能读取同一份 2026-11-22 简报；筛选无任务日期显示明确空结果。
8. 构建前端并重启后端，直接访问 `http://127.0.0.1:8000/#history`，同源页面继续读取真实历史。

本次成功调用报告输入 32,170、输出 1,076，合计 **33,246 Token**。加上前置成功冒烟测试 9,874，共有明确报告的 43,120 Token；此前超时请求未返回用量，不将此数字当成平台账单总数。项目约 100 万 Token 预算的累计硬拦截仍未实现。

可在 backend 目录核对上述真实持久化轨迹：

```powershell
uv run --locked python -m app.diagnostics 079ce755-72ec-4c92-bbfb-36e5b86424e1
```

复现时先保存停用的偏好，点击“立即运行”，根据新的任务 ID 查看诊断。模型可能返回不同轨迹、不同条目或无合格新闻；不要求它重现本次固定序列。已有收录文章会参与跨任务去重，重复生成也会消耗预算。

## 限制与后续验收

- 本阶段不发送新的真实邮件。之前唯一一封配置测试邮件经用户授权发送且已由用户确认收到；新闻简报的真实投递、真实到点触发与重试演示应在单独授权的接收范围内验收。
- 未开启每日调度，不能把本次手动生成宣称为已验证准时定时发送。阶段 F 已记录的明确 SMTP 超时与并发重复触发验证仍需补足。
- `bash` 工具保持注册且 fail closed；Windows 命令隔离未通过验收前不执行宿主命令。本阶段没有修改 Agent 自主性或安全策略。
- 正文提取仍可能包含站点导航，摘要不等同于事实核验；受白名单限制的文章可能被拒绝。未扩大来源访问范围。
- 未做真实设备、屏幕阅读器、400% 缩放、所有浏览器兼容性或网络限速实机验证；网络失败、超时与异步竞态由自动测试覆盖。浅色模式按颜色值检查，不声称完成浅色实机截图。
- 正式安全检查、累计预算控制、备份和部署运维属于后续验收范围，本阶段不自动继续。
