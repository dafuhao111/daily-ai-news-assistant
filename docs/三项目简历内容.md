# 三项目简历内容

## LightRAG 多租户知识库权限网关

岗位：AI 应用开发工程师

时间：2026.11

项目描述：面向多企业共享知识库服务的场景，基于开源 LightRAG SDK 扩展独立 FastAPI 权限网关，支持企业成员管理、知识库级 RBAC、Workspace 隔离、文档管理、带来源的知识问答与操作审计。复用 LightRAG 的图谱及向量检索能力，将身份认证、资源授权和数据隔离前置到检索入口，完成可通过 Swagger 演示的后端原型。

技术栈：Python、FastAPI、LightRAG、Pydantic、SQLAlchemy、SQLite、JWT、NetworkX、NanoVectorDB、pytest、Docker Compose

项目难点：

- 多企业共享服务时，仅依赖登录身份无法限制知识库访问，需要同时校验企业成员关系和知识库角色，并阻止客户端伪造 Workspace 绕过授权。
- 隔离边界需覆盖原文、Chunk、向量、实体关系、图谱与模型缓存，不能只在接口响应阶段过滤结果，也不能仅凭接口拒绝证明底层检索隔离。
- SDK 的多存储写入与业务数据库之间没有跨库事务，上传、删除或进程中断可能留下中间状态，需要保留归属记录和明确的恢复入口。
- 并发首次访问可能重复创建 SDK 实例；同一 Workspace 的读写操作需要协调，避免文件存储状态冲突并保证关闭时释放资源。

核心职责：

- 权限网关：在 LightRAG SDK 前实现 FastAPI 接入层，拆分账号、企业成员与知识库成员模型，配置 Owner、Editor、Viewer 的查询、写入、成员管理及审计权限。
- 检索前鉴权：JWT 仅携带身份，逐请求从数据库读取成员关系和角色；撤权后拒绝旧 Token 的后续请求，跨企业或未授权资源返回 404，角色不足返回 403。
- Workspace 映射：由服务端为知识库生成唯一 Workspace，客户端只提交 kb_id；拒绝请求体、请求头和环境变量中的 Workspace 覆盖，将授权后的映射传入 SDK。
- 实例生命周期：以注册表缓存 Workspace 对应的 SDK 实例，使用初始化锁与二次检查避免重复构建，初始化失败清理资源；同库操作串行，不同库可并行执行。
- 文档与故障处理：接入文本上传、状态查询和删除，按内容去重；上传后严格确认 processed 状态，保留上传失败、删除失败及中断状态，支持删除后重传和幂等删除。
- 操作审计：通过 operation_id 关联开始与完成记录，覆盖查询、上传、删除及权限拒绝；开始审计写入失败时阻断 SDK 调用，日志不记录令牌和文档正文。
- 隔离验证：使用真实 LightRAG SDK、图谱与向量存储，配合确定性模型替身验证 naive / mix 检索与缓存隔离，并覆盖跨租户访问、角色矩阵、撤权及失败恢复。

项目亮点：

- 将知识库权限约束落实到检索之前，结合服务端 Workspace 映射覆盖接口授权与底层数据分区，避免仅靠 Prompt 或前端隐藏实现隔离。
- 通过真实 SDK 的双 Workspace 用例验证原文、图谱上下文和缓存边界，删除一个知识库的文档后，另一个知识库仍能检索。
- 对非事务操作建立可追踪状态与恢复路径，失败时保留文档归属及操作记录，区分业务状态、SDK 处理结果和审计结果。

## 每日 AI 新闻助手 Agent

岗位：AI Agent 开发工程师

时间：2026.11

项目描述：面向 AI 新闻来源分散、订阅内容与个人关注方向不一致的场景，开发基于用户偏好的新闻简报 Agent。用户配置话题、关键词与排除词后，模型通过自主工具调用获取 RSS 候选、检索材料并生成中文简报，保留来源、原文链接与发布时间，支持历史查询和定时邮件投递，完成本机单用户 MVP。

技术栈：Python、FastAPI、LangGraph、LangChain Core、Function Calling、Pydantic、MySQL、SQLAlchemy、Alembic、APScheduler、Vue 3、pytest

项目难点：

- 需要让模型根据任务与工具结果决定调用路径、重复次数和结束时机，同时限制异常循环、超时和上下文增长，保证 Agent 行为可观察、可测试。
- 外部新闻材料不可信，模型输出也可能引用不存在的新闻；需区分来源获取失败、没有匹配内容和生成失败，并在入库前校验来源与材料归属。
- 文件与命令工具具备副作用，需要统一校验参数、限制访问路径和执行命令；新闻抓取还需处理任意 URL 访问与 SSRF 风险。
- Token 消耗跨任务累计且外部调用可能超时，用量未知时不能直接退回额度；简报生成和 SMTP 投递也需要分别记录状态与失败原因。

核心职责：

- Agent 循环：基于 LangGraph 构建“模型决策—工具执行—结果回传”循环，通过 Function Calling 获取模型请求，以匹配调用 ID 的 ToolMessage 回传观察结果。
- 工具接入：统一注册 RSS 获取、任务候选检索、原文读取及本地文件等 8 个工具，使用 Pydantic 校验参数，并将未知工具和执行错误转为结构化结果供模型处理。
- 权限与资源控制：限制任务工作目录、文件类型、写入范围与命令白名单；对新闻域名、解析地址和跳转实施校验，设置模型请求超时、任务超时及工具轮数上限。
- 简报证据校验：校验模型 JSON 输出，限定引用当前任务已获取的候选材料；由服务端填充来源、链接与发布时间，拒绝无依据引用和排除词命中，来源失败时提示覆盖不足。
- 累计预算：基于 MySQL 原子条件更新预留额度，按模型实际输入输出用量结算；超时或用量缺失时保留额度并标记待核对，预算账本持久化且重启不清零。
- 调度与投递：使用 APScheduler 按用户时区执行每日任务，持久化偏好快照、任务、简报和投递记录；邮箱验证后投递，保留生成成功但推送失败的结果并支持有限重试。
- 前端与验证：基于 Vue 3 对接偏好配置、简报阅读、历史查询、任务状态和预算页面；通过不同模型响应、重复调用、错误回传及预算用例验证执行契约。

项目亮点：

- 将模型自主决策与业务校验分层，工具路径由模型决定，简报保存由服务端证据规则约束，既保留调用灵活性，也阻止无来源结果直接落库。
- 通过“预留—结算—未知用量保留”管理累计 Token 预算，覆盖并发请求、超时及进程重启场景，避免仅依赖单次输出长度限制成本。
- 打通偏好配置、新闻获取、结构化生成、历史留存与邮件投递，保存可排查的工具轨迹，并完成真实新闻邮件收件验证。

## 星票智能客服 Agent

岗位：AI Agent 开发工程师

时间：2026.08 - 2026.09

项目描述：面向票务平台售前咨询和售后服务，基于 Spring AI 构建支持订单查询、业务规则问答、多轮对话和知识溯源的智能客服。接入退票、入场、票价、会员积分等知识文档，以显式工作流完成意图识别、业务取数和答案生成，结合短期会话与长期偏好提供上下文回答，并通过 SSE 返回内容与执行状态。

技术栈：Java 17、Spring Boot 3、Spring AI、MySQL、Redis Stack、Embedding、RRF、Apache Tika、OpenFeign、Sentinel、JWT、Reactor、MCP、Docker Compose

项目难点：

- 订单查询与业务规则咨询容易混淆，优惠码或凭证编号不应直接触发订单服务，需要先识别意图，再按分支取数，避免模型自由选择工具带来的误调用。
- 规则问答同时包含语义近似和精确关键词，单一路径检索容易遗漏相关资料，需要对齐向量检索与关键词检索的分片，并保留可引用来源。
- 多轮上下文会持续增长，长期偏好又需要跨会话保留；需划分短期消息窗口和长期记忆，限制抽取范围并过滤订单号、手机号等敏感内容。
- 检索、订单服务和模型生成可能分别失败，需要向前端展示实际执行状态、保留明确的降级响应，并避免记忆抽取影响主回答完成。

核心职责：

- 显式编排：将主回答流程拆分为意图分类、确定性取数与成文，按订单、知识库和闲聊三类分流；分类与成文分别调用对话模型，成文客户端不再绑定业务工具。
- 业务工具：封装订单查询、知识库检索和时间工具，通过 OpenFeign 调用订单服务，区分未找到、服务异常等结果；订单号缺失时保留追问信息，避免编造查询条件。
- 文档入库：读取 Markdown 规则资料，并通过 Apache Tika 接入上传文档解析；使用 TokenTextSplitter 切分，写入 Redis 向量存储及关键词原文池，保留文件来源元数据。
- 混合检索：结合向量召回与中文双字滑窗关键词匹配，各取候选后按分片 ID 进行 RRF 融合，返回 Top 3 材料及来源，供回答阶段引用。
- 会话管理：按用户与会话构建 conversationId，校验会话归属并通过 JDBC 将消息保存到 MySQL，使用 50 条消息滑动窗口控制主对话上下文。
- 长期记忆：在回答完成后异步抽取用户明确表达的稳定偏好，校验类别、键名、长度及数量；过滤敏感字段与长数字，按用户保存，并提供记忆查询和删除入口。
- 交互与复用：通过 Reactor SSE 返回执行状态和流式回答，接入 Sentinel 限流与异常兜底；将已有工具通过 Spring AI MCP 暴露，复用同一组 Spring Bean。

项目亮点：

- 以显式工作流固定业务取数边界，将模型的意图判断与确定性服务调用分开；主回答链路包含分类、成文两次对话模型调用，长期记忆抽取在回答后异步执行。
- 组合语义召回、中文关键词匹配与 RRF 融合，使用统一分片 ID 对齐双路结果，并在检索材料中携带文件来源。
- 将 MySQL 持久化的短期会话与长期偏好分层管理，对抽取结果实施结构和敏感信息过滤，兼顾上下文连续性与记忆内容约束。
