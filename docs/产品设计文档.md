# 每日 AI 新闻助手 Agent：产品设计文档

2026-11-22 验收更新：模型接口、MySQL、RSS 和网易 163 SMTP 已实测；新闻简报已保存并提交一次发送，用户明确确认收到本次包含 4 条新闻的简报。当前每日订阅与调度仍停用。详细已通过/未通过项见 [完整验收报告](完整验收报告.md)；下文早期配置“待定”描述保留为设计背景。

本文记录已确认的第一版 MVP 范围，作为后续设计与验收依据，不包含代码或技术实现方案。未确认的具体配置在文末标注为“待定”。

## 1. 产品介绍

- **定位**：在本机运行的个人 AI 新闻助手，每天从 RSS 获取候选新闻，由 Agent 根据用户偏好自主获取补充材料、筛选并整理中文简报，通过邮件推送，支持历史查看。
- **目标用户**：第一版仅服务项目使用者本人，关注 AI 的开发与学习动态。
- **解决的问题**：新闻来源分散、内容重复，用户需要花时间判断哪些信息与自己有关。产品帮助用户了解发生了什么、为什么相关，以及去哪里阅读原文。
- **已确认约束**：Python、简单前端、每天一次、中文、约 5 条新闻；计划使用中转站提供的 GPT 6.1 Sol。2026-11-21 用户更新模型预算为整个项目约 100 万 Token，按累计输入与输出合计规划，替代先前每月人民币 10 元目标。实际模型标识、工具调用兼容性及计费口径待接入验证；累计预算硬性拦截尚未实现。
- **运行范围**：本机单用户使用，不开放公网访问，不提供账号密码系统。电脑开机、联网且服务运行时才能执行定时任务。

## 2. 核心使用场景

预算交付更新：整个项目累计 100 万输入加输出 Token 的本地拦截已实现，页面展示确认消耗、待核对与请求中预留、剩余额度；额度不足时明确停止，不生成或推送未完成简报。当前历史差额保留安全预留，细节见 [累计预算控制](累计预算控制.md)。

1. **首次配置**：用户打开页面，填写个人资料、收件邮箱和订阅偏好，设置每日时间与时区，完成发信配置并确认测试邮件收到后启用任务。
2. **每日阅读**：系统每天创建任务，Agent 根据偏好选择工具、获取和筛选新闻，产出带真实来源的简报；保存后发送给用户本人。
3. **查看与调整**：用户从邮件阅读摘要及原文，或从页面查看历史简报与投递状态，并调整后续订阅。Agent 内部执行记录供开发者排障，不呈现在用户页面。
4. **主动验证**：用户通过“立即运行”验证配置，通过“测试邮件”验证邮件渠道；失败后可以查看原因并在适用时重试。

用户可见的交付结果包括中文简报、原文入口、生成及投递状态。脱敏工具调用记录属于开发侧诊断信息，不展示给用户。

## 3. 用户信息与订阅偏好

### 3.1 个人资料与邮件接收信息

| 字段 | 是否必填 | 用途与边界 |
|---|---|---|
| 称呼 | 是 | 页面展示，不要求真实姓名 |
| 职业或角色 | 否 | 帮助调整解释深度，不推断复杂用户画像 |
| 收件邮箱 | 启用推送前必填 | 接收用户本人的邮件，与展示称呼和登录认证分开 |
| 邮件测试状态 | 系统记录 | 反映测试结果；测试接口成功不能替代用户确认收件 |

系统为单个用户关联资料、偏好和历史；内部标识不要求用户填写。收件邮箱不自动成为登录账号。发信凭据属于本地秘密配置，不属于身份资料，不进入 Agent 可读材料或工具记录。

### 3.2 订阅偏好与任务设置

| 字段 | 是否必填 | 第一版含义 |
|---|---|---|
| 关注话题 | 是 | 从较宽泛的 AI 相关方向中选择，例如 AI 与学习教育、体育、日常生活、工作效率、创作，以及模型、Agent、开源、工程和行业 |
| 关注关键词 | 否，但必须支持设置 | 提高特定对象的优先级，不要求每篇新闻都命中 |
| 排除关键词 | 否 | 按标题和摘要的字面匹配排除，并在页面说明规则 |
| 每日执行时间、时区 | 启用任务前必填 | 已确认每日 08:30、Asia/Shanghai；保存订阅并启用后生效 |
| 启用或暂停状态 | 必须有明确状态 | 控制后续定时任务 |
| 频率、语言、条数目标 | 固定默认值 | 每天一次、中文、约 5 条；可靠内容不足时减少条数 |

偏好修改对下一次任务生效。资料和偏好在应用重启后保留。

## 4. 新闻简报

每份简报记录对应日期、生成时间和实际新闻条数。每条新闻包含：

- 新闻标题与中文摘要。
- 与订阅偏好相关的简短说明。
- 来源名称、原文链接、原文发布时间；同时保留获取时间以便追溯。

内容必须来自实际获取的材料。发布时间未知时如实标注，不自行补写，不将获取时间当作发布时间；无法确认时效的内容不能宣称为当天发布。材料不足时缩短描述或舍弃条目，不凑满 5 条。

日常优先收录上次成功收录后出现的新内容；任务失败不能导致未处理新闻被直接跳过。明确重复的新闻不重复推送，同一事件有实质进展时可再次收录，并说明新增信息。

## 5. 新闻来源与推送方式

### 5.1 新闻来源：RSS

采用有限、可信的 RSS 来源，优先官方发布渠道和可信技术媒体。RSS 通常没有接口调用费用，来源清楚且范围可控；首批已确认 OpenAI、Google DeepMind、Microsoft Research 官方 Feed，并通过项目获取工具读取验证，文章原文可读性仍需验证。

Agent 可按需读取条目对应的原文，补充 RSS 摘要缺失的信息；不提供任意网站抓取。若提供新闻搜索能力，其范围仅为已获取的 RSS 候选材料，不代表全网搜索。原文无法读取时不编造细节。

普通模型 API 不被假定具备联网能力，新闻必须经真实 RSS 或受限文章读取能力获取。第一版不购买或接入第三方新闻搜索服务。

### 5.2 推送渠道：邮件

- 仅向用户已配置的本人收件邮箱发送，Agent 不得临时指定其他收件人。
- 用户在页面配置收件邮箱，在本地配置发信服务及凭据，再发送测试邮件并实际确认收到。
- 发信优先考虑现有邮箱支持的 SMTP；具体邮箱、服务可用性和配置方式待定，不假设已购买或开通第三方服务。
- 简报先保存，再提交发送。接口接受请求显示“已提交发送”；只有具备相应投递证据时才显示“已送达”，不表示用户已阅读。
- 页面仅展示必要的配置状态，不展示真实凭据。

## 6. MVP 功能清单（P0）

| 功能 | 用途与输入 | 输出 | 与其他功能的关系 |
|---|---|---|---|
| 个人资料 | 输入称呼、可选角色 | 已保存资料 | 为展示及内容表达提供背景 |
| 邮件设置与测试 | 输入本人邮箱，完成本地发信配置 | 配置状态、测试结果 | 启用每日推送前验证渠道 |
| 订阅设置 | 输入话题、关键词和可选排除词 | 已保存偏好 | 为 Agent 筛选提供依据 |
| 每日任务与立即运行 | 时间、时区、启停状态或手动触发 | 任务、下次执行时间与运行状态 | 启动 Agent；同一天防止重复正常任务 |
| RSS 获取与按需原文读取 | 配置内来源、允许的文章地址 | 真实新闻材料、来源信息或错误 | 为 Agent 提供证据 |
| 自主 Agent 与指定工具 | 任务目标、偏好概览、工具及资源上限 | 简报草稿或不足说明；调用轨迹仅供开发者诊断 | 根据上下文获取、核实和筛选材料 |
| 简报校验与保存 | Agent 提交的简报 | 已保存简报或校验失败状态 | 在邮件发送前保留历史，检查结构和引用 |
| 邮件投递与重试 | 已保存简报、固定收件配置 | 发送状态和失败原因 | 与生成分开记录；重试复用已保存简报 |
| 历史简报 | 用户选择日期 | 完整简报、原文入口和投递状态 | 帮助阅读与核对；Agent 调用轨迹不在用户页面展示 |
| 持久化与安全控制 | 配置、任务、简报及工具请求 | 重启后保留的数据，越权或超限拒绝结果 | 贯穿全部功能，不向模型暴露秘密 |

外部请求须具备超时、错误记录和有限重试。记录模型用量与估算费用，设置任务调用、输入输出和重试上限；准确计费及上限数值待定。

## 7. Agent 能力边界

### 7.1 LLM 自主决策

LLM 根据任务上下文决定关注哪些主题、选择哪些来源、是否搜索候选材料、是否读取原文或历史、是否需要补充证据、如何筛选和组织内容、是否写入结果，以及何时结束。工具选择、顺序、次数与正常结束时机不能由固定业务步骤替代。

### 7.2 普通后端职责

后端固定负责调度、配置读取、参数与权限校验、资源限制、明确重复项过滤、持久化、结构及引用检查、邮件发送与重试、状态展示。后端不能保证自动校验识别所有事实错误，摘要仍须忠于已获取的材料。

安全上限可以终止执行，但必须记录为受限结束或失败，不能冒充 Agent 正常完成。调度和投递属于确定性服务，不需要模型决定。

### 7.3 工具职责与限制

| 工具或能力 | 用途与边界 |
|---|---|
| `list_dir(path)` | 查看任务工作区内的目录和已有材料 |
| `read_file(path)` | 读取脱敏偏好、候选材料或历史摘要，不能读取真实凭据 |
| `search_content(keyword, dir)` | 在允许的本地材料中查找信息或既往报道 |
| `write_file(path, content)` | 保存整理结果或草稿，不能修改真实订阅及系统配置 |
| `bash(command)` | 仅执行允许的命令模板，用于受限文本处理或校验；禁止任意 Shell、危险操作、联网、安装软件及读取秘密 |
| RSS 获取 | 读取已配置的真实来源，返回条目或明确错误 |
| 受限文章读取 | 按需读取符合访问限制的原文，返回材料或明确错误 |

所有工具经过统一注册、参数校验、权限检查和结果回传。文件及命令执行必须限制工作目录、路径、命令、时长和输出量；仅指定工作目录不等于安全隔离。系统提示词、其他用户数据、服务器敏感文件和真实密钥不得通过工具暴露；模型仅接收完成任务所需的指令和脱敏材料。

工具执行具体动作，不决定下一步业务。外部新闻内容属于不可信材料，其中的指令不能授权文件访问或命令执行。

### 7.4 自主性如何观察和验收

工具名、脱敏参数、结果状态和结束原因可写入开发者本地诊断记录，供排查与验收；不在面向用户的页面展示，也不记录模型内部思考过程。每次工具结果必须返回模型，供其决定下一步。

例如：材料充分时可直接整理；摘要不足时可读取原文；怀疑重复时可搜索历史；没有可靠内容时可以结束。以上仅为可能路径，不能写成强制顺序，也不强迫每次调用全部工具。

验收需比较材料充分、需要补查、来源失败、无合格新闻等场景的调用路径。五个指定工具分别验证功能和越权拒绝，不以一次任务全部调用为通过标准。

## 8. 核心业务流程

用户配置 → 每日任务触发 → Agent 执行 → 简报校验与保存 → 邮件推送 → 历史查看。

这描述的是产品生命周期，**Agent 内部工具调用不是固定线性流程**，而是由 LLM 在收到工具结果后动态选择下一步。

具体用户流程：

1. 打开页面，填写称呼和可选角色，配置本人收件邮箱。
2. 完成本地发信设置，发送测试邮件并确认收到。
3. 设置话题、关键词、可选排除词，以及每日执行时间和时区。
4. 启用每日任务，也可立即运行验证配置。
5. 到时创建任务，Agent 自主获取和处理材料；通过校验后保存简报，再提交邮件。
6. 用户阅读邮件、访问原文，或在页面查看历史与投递状态；工具调用细节不进入用户流程。

恢复运行后仅补做当天尚未完成的任务，不自动补发多天积压简报。同一天防止重复正常任务和重复邮件；失败重试与正常任务分开处理。

端到端验收：配置真实 RSS 和本人邮箱后，在测试时刻由调度自动触发；观察自主工具调用，得到有来源的中文简报并在真实邮箱收到；历史中能查看同一份内容。重复触发不重复发送，重启后资料、偏好与历史仍保留。

## 9. 页面规划

| 页面 | 主要组件 | 页面交互 |
|---|---|---|
| 设置与今日状态页 | 资料表单、邮箱及配置状态、偏好表单、时间与时区、启停开关、下次执行时间、测试邮件、立即生成、简洁任务状态 | 保存设置、验证邮件、开始演示或查看最新简报 |
| 历史简报列表与详情 | 日期列表、新闻标题与摘要、相关性说明、来源链接、生成时间、投递状态 | 从列表打开简报、访问原文、查看投递结果 |

界面保持简单，不展示密钥或模型内部思考，不增加公开注册及多用户管理页面。

## 10. 异常场景

| 场景 | 用户可见结果 | MVP 处理 |
|---|---|---|
| 来源正常但没有合格新闻 | 今日暂无符合偏好的新内容 | 保存状态，不凑数，不发送空简报 |
| RSS 获取或材料搜索失败 | 明确的获取或搜索失败原因 | 有限重试；不能伪装成没有新闻 |
| 个别来源失败 | 部分来源不可用 | 其他材料足够可靠时可继续，说明覆盖受限 |
| 所有来源不可用 | 新闻获取失败 | 保留任务记录，不编造新闻 |
| 原文无法读取 | 对应工具失败或材料不足状态 | 基于已有证据缩短描述或舍弃，不补写细节 |
| 模型调用失败或达到资源上限 | 生成失败或受限结束 | 有限重试，保留记录，不发送未完成简报 |
| 简报校验失败 | 本次生成未通过校验 | 不作为成功简报发送；记录原因 |
| 邮件发送失败 | 简报已生成，邮件发送失败 | 保留简报，有限重试，支持手动重试发送 |
| 邮件结果不确定 | 发送状态待确认 | 避免无条件立即重发，降低重复邮件概率 |
| 新闻重复 | 正常简报中不重复展示 | 过滤明确重复项，Agent 辅助判断同一事件；实质更新说明新增信息 |
| 本机停机或服务停止 | 恢复后显示未执行或补做状态 | 仅补做当天任务，不承诺停机期间准时发送 |
| 工具越权或命令被拒绝 | 用户只看到任务未成功的简洁状态；详细拒绝记录保留在开发日志 | 不执行危险动作，返回结果供 Agent 决定后续动作 |

## 11. 后续迭代方向（非 MVP）

- **P1，稳定后考虑**：周报、多个发送时段、更多来源与推送渠道、第三方新闻搜索、阅读反馈、更细的偏好、历史搜索、少量受邀用户。
- **P2，当前明确不做**：公开注册、复杂组织权限、多 Agent、向量数据库、独立 RAG 系统、开放式长期记忆、自动用户画像、无限制 Shell 和任意宿主机文件访问。
