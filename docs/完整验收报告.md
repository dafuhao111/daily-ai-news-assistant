验收日期：2026-11-22，中国标准时间。范围为既定本机单用户 MVP，包含修复、测试和交付，不增加页面、公开注册、第三方搜索或多 Agent。

结论：**有条件通过，不是所有技术条件均已通过**。核心功能、真实自主循环、新闻保存与 SMTP 提交链路通过。本次新闻邮件的本人实际收件尚待确认；技术方案第 5.2 节的通用 Windows 低权限/进程沙箱没有完成，不把固定 JSON 模板的功能验证当成该项通过。长期每日运行、系统启动托管与下述残余限制不宣称已验证。每日订阅和 `SCHEDULER_ENABLED` 最终均为 false。

| 2. 话题、关键词 | preferences API 保存 11 种话题内的选择、关键词、排除词和时间；Mock 模型收到不同偏好后产生不同调用路径及结果；服务端执行排除词校验 |

| 4. 任务触发 | 手动 API 已实测；真实 APScheduler Cron 在自动测试中到点触发（Mock 模型/RSS/邮件）；本次真实服务由显式一次性计时器触发 |

| 12. 前端状态 | 资料、偏好、运行、空简报、失败、历史、投递状态均来自 API；本次浏览器核验 4 条新闻、来源覆盖受限提示和已提交发送；无页面控制台错误 |

## 2. 五个指定工具

| 工具 | 真实实现 | 允许边界与验证 |
|---|---|---|
| list_dir | 列出当前工作区可见条目 | 限条目数；隐藏文件、reparse point、硬链接等排除；功能与越权测试通过 |
| read_file | 读取有界 UTF-8 材料 | 仅 inputs/history，64 KiB，拒绝绝对/上级路径、链接、秘密名称、二进制及非允许扩展名 |
| search_content | 对当前任务材料做字面搜索 | 目录深度、数量、字节、时间和结果数均有限；不是互联网搜索 |
| write_file | 原子保存草稿 | 只写 drafts 内 txt/md/json；大小及路径检查；不能修改程序、真实偏好或数据库 |
| bash | **本阶段修复为真实执行**受限 JSON 校验命令 | 仅接受 `python -m json.tool inputs或history下的JSON路径`。固定解释器与 argv、shell=False、`-I -S`、stdin 快照、最小环境、2 秒超时、4 KiB 输出、64 KiB 输入和 32 层 JSON 深度；拒绝其他命令/额外参数/元字符/路径越权 |

`bash` 没有开放任意 Shell。隔离参数防止任务目录内的 json.py 或 site 包劫持，子进程不继承模型/SMTP 密钥，使用可信 stdlib，超时由 subprocess.run 杀死并回收。这个范围不等于通用 Windows 低权限进程沙箱，不支持任意命令，也未承诺通用进程树隔离。与技术方案原先要求低权限/进程限制验证后再开放命令的门槛存在范围差异：当前证明的是固定、不接受代码与文件路径输入的 JSON 子进程模板；若原门槛必须严格按通用 OS 沙箱解释，则这一安全条件未通过。建议保留该极窄模板作为 MVP 边界，禁止扩展模板；需要更广命令时另行完成低权限沙箱验收，不以改文档掩盖差异。

另注册 fetch_rss、search_news、fetch_article。联网来自实际 RSS/网页工具；search_news 只检索本任务已取得候选，不是全网搜索。模型自身不需要联网。没有真实材料时，不能通过简报校验冒充新闻成功。

## 3. 本阶段发现与修复

1. **并发重复生成**：入队以 MySQL 用户行锁串行检查，执行以 queued→running 条件更新原子领取；竞争失败者不改写执行者状态。同一用户有活跃任务时不并行新建，当天成功/空结果复用已有正常任务。
2. **投递并发**：领取和人工重试增加行锁，配合条件更新与唯一约束。8 路真实 MySQL 并发验证每种操作只有一个胜者。
3. **重启恢复**：调度关闭仍恢复当天手动任务、将中断发送记 unknown；此前中断的定时任务在调度关闭时记 scheduler_disabled，不继续发信，也不长期阻塞手动任务。调度开启才建立 Cron 和自动重试扫描。
4. **bash 空实现**：从始终 sandbox_unavailable 改成上述受控命令执行，原拒绝测试保留并补充执行、模块劫持、环境隔离、超时、深度、大小及截断测试。
5. **模型客户端生命周期**：完整真实测试曾发现第二个事件循环复用已关闭 HTTP 客户端。改为每个真实 Agent 任务独占 AsyncClient，并在结束后关闭；修复后两项真实模型测试在同一完整测试运行中均通过。
6. **输入资源上限**：每次模型调用前对消息和 Schema 的本地序列化字节计数，默认单次 128,000、任务累计 512,000；超限记 limited/input_limit，不提交超限请求，不截掉材料冒充正常结束。这是应用资源上限，不是供应商计费 Token 上限。
7. **来源覆盖与时间**：部分 RSS 来源失败时把覆盖受限提示保存到简报、页面和邮件；原日期无明确时区时保留原文、UTC 留空，不凭空解释成 UTC。
8. **SSRF DNS 再解析窗口**：真实 HTTP 连接固定到校验过的公网地址，并保留原 Host/TLS SNI 和证书校验，逐跳检查重定向；不再让传输层第二次解析域名切换到私网。
9. **安全依赖**：修复测试依赖中的 critical/moderate 公告及后端设置、dotenv、DNS 依赖公告；提升最低 Python 至 3.11、本机使用已有 3.12.13，锁定 .python-version。旧 Python 3.10 无法选用修复版 dnspython。
10. **验收脚本恢复开关**：真实 MySQL DATETIME 精度与 Python 微秒不一致曾使恢复条件失配。已恢复本机停用状态，代码改为读取落库后的时间并比较完整快照，增加 MySQL 回归；不会覆盖并发用户修改。

## 6. 安全措施与残余风险

| 风险 | 已采取措施 | 边界 |
|---|---|---|
| 任意文件访问 | 服务端选择工作区；相对路径/扩展名/秘密名称校验；拒绝链接和 reparse point；限制大小深度；原子写草稿 | 同一 OS 用户恶意并发替换路径的句柄级竞态未完整证明；需要私有工作区，不能与不可信进程共享 |
| 任意命令与超时 | 固定 JSON stdlib 子进程、shell=False、-I -S、最小环境、2 秒 kill/reap、输入深度及输出上限 | 不提供通用命令沙箱；不允许以本工具运行安装、网络、脚本或任意程序 |
| SSRF/重定向 | 来源配置受控，文章仅用本任务 ID；精确主机、公开 IP、端口/协议、逐跳验证；连接固定 IP，保留 TLS 验证 | DNS 本身依赖 OS 解析器；没有网络层沙箱/防火墙的独立实机验收 |
| 密钥和日志泄露 | 后端环境变量；模型不含邮箱、DB/SMTP 秘密；轨迹只记安全摘要与数字用量；用户 API 不暴露轨迹；日志不记异常正文 | 未进行独立第三方渗透测试；第三方模型供应商仍接收必需的非秘密任务材料 |
| 未授权 API | loopback 监听、Host/Origin/JSON 校验，无宽泛 CORS，仅提供 dist | 本机单用户设计，没有账号认证；不支持公网或局域网部署 |
| 重复邮件 | 入队行锁、每日槽位、原子领取、唯一键、发送前复查目标/验证/启用、有限重试；重启 sending→unknown | SMTP 无跨服务事务，Message-ID 不构成对方去重承诺；unknown 不能保证 exactly-once，只能避免盲重发 |
| 多用户 | API 固定用户 1，读取按归属过滤；内部偏好快照隔离测试通过 | MVP 不提供多用户；公共新闻去重池不是多租户隔离方案，不宣称可直接开放多用户 |
| 预算与新闻质量 | 单次输出、轮数、调用数、输入字节和任务时间限制；真实材料引用和排除词校验 | 无累计账单硬拦截；不自动核验全部事实；RSS 只取有限窗口，未实现无限历史回溯和增量游标消费 |
